# DiffGet · 图片差异提取工具

把两张**相邻帧**的差异提取成一张**带 alpha 的图层 PNG**：把它叠加回「背景图片」上，
**逐像素精确还原「提取图片」**。双击 `run.bat` 即用，Web 页面在 <http://127.0.0.1:9426>。

适用于动画 / 游戏连续帧的素材分离：例如把一帧里多出来的特效层（水花、粒子、光效）
单独抠成图层，再叠到别的帧或重绘后的底图上。

## 特性

- **像素级比较**：任一通道差值 > 容差即算差异（容差默认 0 = 任何差异都提取）
- **一次写出两张**：
  - `<名字>.png` — **素材图层**（默认带 1px 边缘羽化），放到新背景上边缘自然过渡
  - `<名字>_原始.png` — **原色提取图**（硬边、alpha 仅 0/255），当参考或存档
- **「叠加还原」是数学恒等式**：默认路径实测误差 **0.00**，与差异大小无关
- **两种算法模式**：默认「原色提取 + 边缘羽化」；可选回最初的「半透明归因」
  （un-blending 反解，输出 250 档 alpha 的真正半透明图层）
- **大图多进程并行**：≥400 万像素自动启用，任何并行异常自动回退单进程
- 结果先入缓存、**7 天自动删除**；一键永久保存到 `out\`
- **纯本地运行**：不联网、不上传任何图片
- 自带 `selftest.py` 自检（合成夹具，不需要任何外部素材）

## ⚠ 使用前必读：画布尺寸

**在 Photoshop 里请直接打开「提取图片」作为画布（尺寸就是原图尺寸），再把图层拖进去 ——
不要「新建文档」后拖入并缩放。**

旧版「半透明归因」的图层含 42,632 个「alpha<16 却彩度≥200」的极端色像素，
一旦被缩放到别的画布尺寸，插值会把极端色渗进邻居，**凭空产生彩色杂点**
（实测仅缩放到 2730×1536 就多出 2,931 个这样的像素）。详见下文「绝不要缩放这个图层」小节。

输出图四角的 4×4 纯红标记就是给你核对尺寸与对齐用的。

## 页面使用说明

1. **两个图片框**
   - 「提取图片（图片A）」：差异像素的颜色来源
   - 「背景图片（图片B）」：对比基准
   - 每种图都支持三种方式确定路径：
     - **拖拽**图片到框内
     - 点击「选择图片…」在文件对话框中挑选
     - 在路径输入框**手动输入本地路径**（如 `E:\pic\a.png`）后点「载入路径」或按回车
2. **参数**
   - 容差：0-255，默认 0（任何像素差异都提取）；调到 2-3 可清理时域噪点（实测 1920×1080 截图中 dmax 1-2 的噪点有 34183 个）
   - 取色来源：差异像素取哪张图的颜色，默认图片A（可切换B）
   - 边缘羽化：0（硬边）/ 1（**默认**）/ 2 / 3
   - 杂色抑制：仅「半透明归因」开启时生效（关闭 / **标准（默认）** / 强）
    - 半透明归因：**旧版算法，可选，默认关闭**。关闭即「原色提取 + 边缘羽化」（推荐，数学上不可能产生杂色）；开启后回到最初的 un-blending 反解路径，直接输出带 alpha 值的透明 PNG（250 档 alpha），但**该图层绝不能被缩放**，否则会渗色（见「使用前必读」）
   - 预览原色图：预览窗口显示哪一张（默认显示羽化素材图层）；仅默认路径有效
   - 四角定位像素：默认开启（PS 定位用），可取消勾选
3. 点「⚡ 开始提取」，下方预览窗口显示提取结果（棋盘格背景便于观察透明区域，可切换纯黑/纯白/纯灰背景）
4. 统计信息：输出尺寸、差异像素数、差异占比、耗时、并行引擎、差异外接框、半透明差异像素、半透明归因开关状态、文件大小
5. 「💾 保存到 out 目录」：提取按钮下方的保存区**常驻可见**，提取成功后自动启用；点击即渲染并永久保存到 `out\` 目录（缓存中的副本 7 天后仍会被清理，不影响已保存文件）。保存文件名可自定义，重名自动加序号
6. **切换提取模式**：勾选/取消「半透明归因」后需**重新点一次「开始提取」**方才生效（该参数在提取时决定算法路径）；生效后「透明判定」滑块会出现，拖动可实时预览，保存时按同一取值导出

- 羽化半径 0/1/2/3 都不破坏「叠加还原」，且半径越大半透明环越宽
- 原色提取图是硬边（差值区 alpha 恒为 255，掩码外恒为 0）

- 旧版「半透明归因」带丰富 alpha 档位且叠加还原误差 `<= 3`
- **预览 == 导出**：`render_at(t=1)` 与关键帧 `K1` 位级一致
- **多进程与单进程结果逐像素一致**
- Web API（`/api/extract`、`/api/save`）端到端可用，产物与内存计算一致
- 非法参数（`feather_radius=9` / `tolerance=999` / `source=c`）返回 400

## 并行优化说明

- 图片总像素 ≥ 400 万（约 4K 尺寸）时自动启用**多进程并行**：按行切分 band（band 数 = 进程数 × 2 做负载均衡），进程池用 `spawn` 方式启动（避免与 Web 服务多线程环境 fork 死锁）
- 小图使用单进程 numpy 向量化（启动进程池的开销不划算）
- 并行路径出现任何异常都会**自动回退单进程**，不会导致任务失败
- 进程数默认取 CPU 核心数，可用 `--workers` 或环境变量调整

## 核心算法：精确合成提取（默认）

对每个像素比较两图 RGBA（任一通道差值 > 容差即算差异，且两图都全透明者视为相同）：

| 情形 | 输出 alpha | 输出颜色 |
|---|---|---|
| 差异像素，源像素不透明（alpha=255） | **255** | **取色来源的原始颜色** |
| 差异像素，源像素半透明（0 < src_alpha < 255） | **src_alpha**（保留原始透明度） | 取色来源的原始颜色 |
| 差异像素，源像素全透明（src_alpha=0） | 0 | （无内容可提取） |
| 非差异像素 | 0 | 无关 |

**为什么这样就是正确的**：把结果按 alpha 叠加到底图上 `out·A + (1-out)·B`，
alpha=255 时该式恒等于 `out`（即来源原色），alpha=src_alpha 时恒等于源图覆盖在底图上的外观。
因此**叠加结果逐像素精确等于来源图**——这是数学恒等式，与差异大小无关，
**数学上不可能产生杂色**。整个路径没有除法、没有颜色反解、没有中值替换。

实测（真实 1920×1080 连续两帧 `0240_01_20` / `0240_01_21`，容差 0）：

| 指标 | 新算法（默认） | 旧 un-blending (t=100) | 旧 un-blending (t=50) |
|---|---|---|---|
| 复合还原误差 max / p99 | **0.00 / 0.00** | 2.36 / 2.00 | 1.00 / 0.54 |
| 彩度 p90 | **40**（原图 40） | 230 | 43 |
| 「至少一通道触 0/255」占比 | **8.3%**（原图 8.3%） | 99.6% | 8.3% |
| 可见像素中 alpha<64 占比 | **0%** | 82.5% | 0% |

| 产出 | 文件名 | 用途 |
|---|---|---|
| **羽化素材图层** | `<名字>.png` | 放到**新背景**上使用：掩码边界外侧带 alpha 渐变，边缘自然过渡 |
| **原色提取图** | `<名字>_原始.png` | 硬边（alpha 仅 0/255）、差异像素取来源图原色；当参考图或存档 |

页面上「预览原色图」勾选框可切换预览哪一张。两者在**掩码内部完全一致**（颜色=来源原色、alpha=255），
只有边界外侧的羽化环不同。

## 边缘羽化（默认 1px）

- 二值差异掩码的直接边缘是硬边，放到新背景上会出现**锯齿**
- 羽化在掩码**边界外侧**生成 alpha 渐变（半径 R 时第 d 圈 `alpha = 1 - d/(R+1)`），
  颜色按**精确解族**反解：`C = B + (A - B) / alpha`（B=底图色，A=来源外观色）
- 该式与复合方程 `alpha·C + (1-alpha)·B = A` 等价，因此**羽化不破坏「叠加还原」**：
  实测半径 0/1/2/3 的复合还原误差均为 **max = 0.00**，同时边缘获得 128 / 85·170 / 64·128·191 的渐变 alpha
- alpha 有闭式下限（保证反解颜色不越界），下限由「最小 alpha 解」钳住；颜色始终由羽化曲线给定的 alpha 反解，
  **绝不采用那个极端解**——那正是旧版杂色的来源
- 为什么不做掩码模糊：模糊会把掩码糊成约 51% 的半透明带，且那些像素颜色仍是原色、与 alpha 不匹配
  （叠加回底图无法还原来源图）。实测 1920×1080 截图中 401625 个掩码像素里有 205985 个会落入该过渡带
- 页面「边缘羽化」可选 0（硬边）/ 1（**默认**）/ 2 / 3；CLI 用 `--feather N`（旧名 `--aa-radius` 仍兼容）
- 统计口径不受影响：差异像素数、外接框始终按二值掩码计算，不含羽化环

实测（1920×1080，容差 0）：

| 羽化半径 | 羽化环像素 | 环 alpha | 复合还原误差 max | 耗时 |
|---|---|---|---|---|
| 0（硬边） | 0 | — | **0.00** | 87 ms |
| 1（默认） | 44,097 | 128 | **0.00** | 131 ms |
| 2 | 72,083 | 85 / 170 | **0.00** | 140 ms |
| 3 | 95,173 | 64 / 128 / 191 | **0.00** | 154 ms |

## 半透明像素的严谨判定

- `alpha == 0` → **全透明**：该像素不可见，其 RGB 无定义
- `alpha == 255` → **不透明**
- `0 < alpha < 255` → **半透明**
- 两张图在该像素**都全透明时视为相同**，RGB 不参与比较——避免“透明区域 RGB garbage 不同”造成的误报（不同工具保存的 PNG 透明区 RGB 可能携带任意值）
- 提取时**保留源像素的透明度**：源像素半透明时输出 alpha = 源像素 alpha；全透明时输出 alpha = 0
- 结果统计中会报告差异像素的透明度构成（不透明 / 半透明 / 全透明数量），页面显示“半透明差异像素”

## 半透明归因（旧版算法，可选，默认关闭）

> ⚠️ 打开后回到最初的 un-blending 路径：**直接输出带 alpha 值的透明 PNG**（这正是最早那版的效果），
> 但对**不透明源图（普通截图）边缘会出现彩色杂色**。仅在需要「带 alpha 的素材图层」且能接受杂色时使用。

### 怎么切回去

1. 勾选参数区的「**半透明归因**」（标签：旧版算法）→ 出现「**透明判定**」滑块与警告条，
   「边缘羽化」「预览原色图」同时置灰（这两项在旧版路径下不生效）
2. **重新点一次「⚡ 开始提取」**（该参数在提取时决定算法路径）
3. 拖「透明判定」滑块实时预览；保存时按同一取值导出，**预览与导出逐像素一致**

### ⚠ 致命使用陷阱：绝不要缩放这个图层

旧版 un-blending 的解族会把差异像素解成「**极低 alpha + 极高饱和色**」。
实测该图层里有 **42,632 个** `alpha < 16 却 chroma ≥ 200` 的像素（占可见像素 **11.60%**），
例如 `alpha=3、C=(255,0,0)`。

这些像素本身几乎不可见，但**一旦图层被缩放到别的画布尺寸**，插值会把它们的极端颜色
**渗进邻近的可见像素**（直通 alpha 插值等于对 R/G/B/A 各自独立重采样），
于是**凭空出现既不属于来源图、也不属于背景图的颜色**——就是用户看到的"无关颜色 / 杂色"。

实测（`0240_01_20` / `0240_01_21`，缩放到 2730×1536，即 ×1.42，再叠加到底图上）：

| 产出 | `alpha<16 且 chroma≥200` 像素 | 缩放后**凭空多出**的颜色（彩度 >20） | 渗色误差 max |
|---|---|---|---|
| **旧版半透明归因** | **42,632（11.60%）** | **2,931 px**（>40 的还有 1,027 px，彩度最多多出 78） | **85.4** |
| 默认羽化（原色 + 羽化 1px） | 0 | **0 px** | 20.2 |
| 原色提取（硬边） | 0 | **0 px** | 40.7 |

**结论与用法**

- 旧版图层**只在 100% 尺寸下使用**：在 PS 里**直接打开「提取图片」作为画布**（尺寸就是原图尺寸），
  再把提取层拖进去——**不要新建文档后拖入缩放**。四角红色定位像素可用于核对尺寸与对齐。
- 若工作流**必须缩放**（例如重绘后分辨率不同），请改用**默认路径（原色 + 羽化）**：
  它掩码内 alpha=255、颜色=来源图原色，**没有任何极端色像素，缩放不产生任何凭空颜色**。

### 算法

问题背景：对没有透明信息的图（JPEG、flattened 导出等），无法从单帧判定差异元素原本是否半透明。开启后对每个差异像素求解 (α, 真实色 C)，使 `α·C + (1-α)·底图 = 提取图` 逐通道成立：

- 提取时服务端预存两个关键帧 K0/K1 与两份渲染辅助图（来源覆盖到底图后的外观 S、底图 O）并写入缓存
- 中间判定值沿精确 alpha 解族渲染：

```
α(t) = max((1-t)·α₀ + t·α₁, α₁ + 0.5)     // 钳到解族下限，颜色才不越界
C(t) = O + (S - O) / α(t)
```

- 预览（浏览器）与保存（服务端）使用完全相同的公式、标度与取整，因此同一判定值下预览与导出逐像素一致
- CLI 用 `--semi-attribution`（开启）配合 `--transparency N`（百分比，默认 0）

### 三个模式的实测对比（同一对 1920×1080 真实帧，容差 0）

| 模式 | 复合还原误差 max / p99 | 彩度 p90 | 触 0/255 占比 | alpha<64 占比 | 低α高彩度 | 半透明像素 | alpha 档位 |
|---|---|---|---|---|---|---|---|
| **原色提取（默认）** | **0.00 / 0.00** | **40** | **8.3%** | **0%** | **0** | 0 | 2 |
| **羽化 1px（默认）** | **0.00 / 0.00** | **41** | **10.6%** | **0%** | **0** | 44,097 | 3 |
| 旧版 t=100（完全归因半透明） | 2.36 / 2.00 | 230 | 99.6% | 82.5% | 114,872 | 362,545 | 250 |
| 旧版 t=50（插值中值） | 1.00 / 0.54 | 43 | 8.3% | 0% | 0 | 396,728 | 128 |

读法：

- **默认路径两项产出都数学精确**（误差 0.00），且彩度、触边界率与原图同级——这就是"不可能有杂色"的量化含义
- 旧版 **t=100** 才是用户最初看到的那版：带 250 档 alpha 的真正半透明图层，但 82.5% 的可见像素 alpha<64、
  彩度 p90 冲到 230、99.6% 触 0/255，边缘即彩色杂色
- 旧版 **t=50** 指标反而干净（彩度 43、无低α高彩度），但它的语义只是"把整层按 50% 不透明度绘制"，
  并非素材本身半透明——需要素材图层时没有意义
- 三档「杂色抑制」（0/1/2）对 t=100 的改善有限（低α高彩度 115,565 / 114,872 / 114,133），
  说明杂色来自"最小 alpha 解"本身，不是噪点，滤波压不掉

**为什么默认关闭（根因）**：单通道方程在 (α, C) 下欠定，实现取"使 C 落在色域内的最小 α"，于是解出「极小 alpha + 极端颜色」。对**不透明源图**而言这等于把 1-2 级时域噪点放大 `1/α` 倍：实测 82.5% 的可见像素 alpha<64、99.6% 至少一个通道触 0/255、彩度 p90 高达 230（原图 40），肉眼即严重杂色。旧版"50% 叠加更严重"的成因是 t=50 时 alpha 被插值抬高，更大的可见面积带着同样的放大误差显形；当前实现已用解族下限钳位（`α₁ + 0.5`）与 uint8 饱和钳位修掉溢出，故 t=50 的指标已回归干净。

**un-blending 的鲁棒性设计（仅该旧版路径生效）**

1. **外观折算**：来源图自身带 alpha 时，先折算为"覆盖在底图上的外观"再求解
2. **微差异置空**：所有通道差异 ≤ 2 的像素不归因透明度，避免 1-2 级差被外放成饱和色
3. **杂色抑制（可调档位，默认"标准"）**：对解出的颜色做 3×3 掩码中值滤波；替换受复合误差硬约束（仅当 `α·|ΔC| ≤ 2` 才接受）。页面下拉：关闭 / **标准（默认）** / 强；CLI 用 `--despeckle 0|1|2`。**该选项对默认路径无任何影响**

## 【结论】「删除型」后处理为什么不可行（已实测并移除）

曾经实现过一版「二次清理」：圈定 alpha>0 的区域，把"会向新背景注入可见彩色的像素"
直接置空（判据 `speck = α·chroma(C)`）。**该功能已被证明有害并彻底移除**，
原因是一条硬数学约束：

```
α·chroma(C) = α·(max C − min C) ≤ 2·α·max|C − B| = 2·|A − B| = 2·d
```

即 **一个像素向新背景注入的可见彩色，永远不超过它真实帧间差的两倍**。
推论：凡是**看得见**的彩点（speck ≥ 24），其背后必然是 **d ≥ 12 的真实内容**；
把它删掉，就是在叠加回原底图时留下同样量级的空洞——**用可见的空洞换可见的彩点，
是纯粹的等量交换，不是优化**。

实测（`0240_01_20` / `0240_01_21`，1920×1080，旧版 t=100 + despeckle=1）：

| 被删像素的真实帧间差 d | 像素数 | 「强」档删掉的比例 |
|---|---|---|
| 1–2 | 34,183 | 100%（微差异置空，属正常规则，代价 ≤2） |
| 3–5 | 78,948 | 2.6% |
| 6–16 | 157,895 | 2.7% |
| 17–64 | 121,934 | **20.6%** |
| 65–255 | 8,665 | **82.1%** |

「强」档一共删掉 38,634 个像素，叠加回 `0240_01_21` 后与 `0240_01_20` 的差异：

| 产出 | 叠加还原误差 p99 | 误差 >8 的像素 |
|---|---|---|
| 旧版 + 二次清理「强」 | **36.0** | **35,776** |
| 旧版（原样，不清理） | **2.00** | **0** |
| 默认路径（原色 + 羽化 1px） | **0.00** | **0** |

**所以：提取图层不需要、也不能靠"删像素"来去杂色。**
若素材要放到**别的**背景上、介意旧背景透出，正确的旋钮是「**透明判定**」滑块：
它沿精确 alpha 解族抬高 α（`C' = B + (A−B)/α'`），**叠加回原底图仍然精确**，
只是让图层更不透明、旧背景透出更少——这是唯一无损的调法。

### 【不变量】不许出现空洞

差异掩码内任何 `|d| > 2` 的像素，**alpha 必须 ≥ 1**。
数学保证：`has_info = any(|d_c| > 2)` 为真 ⇒ `alpha_min = max(alpha_raw, 1.0) > 0`。

该不变量由 `verify_usercase.py` 的 U1 持续守护——**任何未来"造洞"的功能都会立刻被它抓住**
（当初那次事故正是它缺席导致的）。

**四角定位像素（默认开启）**

- 在输出图四个角绘制 4×4 纯红实心标记（alpha=255），紧贴画布边缘——在 Photoshop 中选中标记即可精确知道输出图的边界，方便把提取层对齐回原图位置
- 可手动开关：页面勾选「四角定位像素」；CLI 用 `--no-corner-markers` 关闭
- 标记不参与差异统计，始终实心

## API 简介

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 页面 |
| POST | `/api/load` | 校验本地路径并返回预览图 `{"path": "..."}` |
| POST | `/api/extract` | 执行提取，返回双产出与关键帧 `{"a":{"type","value"},"b":{...},"tolerance":0,"source":"a","feather_radius":1}` |
| GET | `/cache/<文件>` | 缓存图片（含 `_k0`/`_k1` 关键帧与 `_s`/`_o` 渲染辅助图） |
| POST | `/api/save` | 渲染并保存 `{"file":"提取结果ID","name":"可选.png","t":0-100,"corner_markers":true,"semi_attribution":false}` |
| POST | `/api/open_out` | 打开 out 目录 |
| GET | `/api/info` | 服务信息（目录、缓存天数、CPU 核数等） |

图片参数 `type` 为 `path`（本地路径）或 `data`（data URL）。`feather_radius` 为边缘羽化半径（0-3，**默认 1**，0=硬边；旧名 `aa_radius` 不再接受）；`semi_attribution` 为「半透明归因」旧版算法开关（默认 `false`）。`/api/extract` 响应含 `file`（提取结果 ID，保存时传给 `/api/save`）、`plain_url`（原色提取图）与 `feathered_url`（羽化素材图层），另含 `keyframes`；默认路径不生成 `render_aux`（省掉两次整幅 PNG 编码与传输），仅半透明归因开启时才返回 `render_aux`。`/api/save` 一次写出**两张**（`saved` = 当前模式主图、`plain_saved` = 原色提取图）；其 `t` 为透明判定百分比，仅在半透明归因开启时有意义（`t=100` 即旧版完全归因，`t=0` 等价于原色提取）。

## 方案调研结论

核心需求是「把两张图片的差异像素提取成透明 PNG」。调研了现有开源方案：

- [pixelmatch](https://github.com/mapbox/pixelmatch)（JS）：像素级对比，输出的是差异**对比可视化图**（高亮差异区域），不是透明提取图
- resemble.js / Blink-diff：同类图片对比可视化方案
- PIL `ImageChops.difference`：输出的是逐通道差值图（不透明），无法直接得到「差异像素 + 原色 + 透明背景」

没有现成项目直接满足「差异像素透明 PNG」需求，因此按需求用 **Python（Pillow + numpy + multiprocessing）自研**实现。

## 常见问题

- **端口被占用**：设置环境变量后启动，如 `set DIFFGET_PORT=9427 && python web_app.py`
- **依赖安装失败**：手动执行 `python -m pip install -r requirements.txt`（需要 Python 3.9+）
- **想局域网访问**：`set DIFFGET_HOST=0.0.0.0` 后启动（注意此时同局域网均可访问）
- **缓存文件去哪了**：缓存目录 `cache\` 中超过 7 天的文件会在服务启动和每次提取时自动清理；点过「保存」的文件在 `out\` 中永久保留
